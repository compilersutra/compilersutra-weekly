### 6. [GCC] Fix return value ABI handling for nullptr_t

**What changed**  
Starting with r0-104773-g0d697034b7eecd in GCC 4.6 (which introduced
initial C++11 and std::nullptr_t support), arguments of type nullptr_t,
std::nullptr_t, and decltype(nullptr) are passed in registers.  However,
return values are erroneously returned in memory, violating the psABI.

**Why it matters**

### 8. [GCC] Add support for 'omp allocate' directive

**What changed**  
This patch adds support for the 'omp allocate' directive in C++. In parity
with the C front end, each variable found in an allocate directive has an
'omp allocate' attribute added to it to mark it for transformation during
lowering. This patch makes minimal modifications to gimplification aside
from clearing C++ specific diagnostic information. This attribute is added
to VAR_DECL nodes during parsing to ensure correct diagnostics. Due to the
nature of this feature, the 'omp allocate' attribute is parsed after each
VAR_DECL, thus care must be taken to preserve ordering with regards to
dependent attributes and non-dependent attributes. This is fairly brittle,
but appears to be a better solution than marking the attribute itself
dependent to avoid copying the attribute each time the VAR_DECL is
substituted into.

**Why it matters**  
Matters for CPU compiler engineering. Lives in the Frontend of the pipeline. The same commit touches tests — use those as the reproduce entry point. Primary audience: CPU developers, Frontend engineers.

**Who should care**  
CPU developers, Frontend engineers

**Type:** New capability · **Stage:** Frontend · **Domain:** CPU

**Source:** [`9bafebd0`](https://github.com/gcc-mirror/gcc/commit/9bafebd00ec54498bcc0adc9a8dbb74c3624dce4)
